# Валидация: unit-тесты и границы live-покрытия

[Главная и карта документации](../../README.md) | [Карта документации](../README.md)

Последний зафиксированный набор: 120 прошедших unit-тестов. Это отчет о прежней проверке реализации, не новый запуск тестов при переносе документации.

Материалы ниже сохраняют ход исследования. Последующие записи могут уточнять ранние гипотезы; ограничения приведены рядом с результатами.

## Проверка реализации

Unit-тесты запускаются без устройства:
`python -m unittest discover -s tests -v`.
Текущий набор: **120 тестов, все прошли**; также прошли compileall и diff --check
после изменений запуска и закрытия.
Покрыты парсер, офлайн-версия вне таблицы, состояния, ошибки, таймауты,
однократность нажатий, ожидаемое устройство/Current, подтверждения,
валидация ZIP, принадлежность файлового диалога и запрет CLI без `--yes`.
На новом M4T read-only проверены Current 17.01.0516, 10 строк и idle.
После запущенного пользователем Offline Upgrade SDK прочитал complete,
17.02.0501, 100%, затем Current 17.02.0501 и 10 строк без CURRENT.
Тем самым корнер-кейс офлайн-версии вне онлайн-таблицы проверен на устройстве.
Метод SDK `refresh()` прошел отдельный end-to-end прогон на устройстве
2026-10-04. Downgrade проверен с продолжением существующего диалога после
исправления парсера. Готовые методы Upgrade и Offline Upgrade пока не прошли
отдельный end-to-end прогон; их предыдущие успешные прошивки выполнялись
экспериментальными скриптами/пользователем.

### Ранний снимок набора тестов

Следующая запись относится к начальному этапу, до расширения набора до 120 тестов.

Парсер и сессия проверяются набором из 22 unit-тестов командой
