# Windows SDK: чтение, операции, запуск и CLI

[Главная и карта документации](../README.md)

Обычный режим DJI Assistant 2 через UIA. Запись требует явного подтверждения, ожидаемых модели и Current; неизвестный результат нельзя автоматически повторять.

Материалы ниже сохраняют ход исследования. Последующие записи могут уточнять ранние гипотезы; ограничения приведены рядом с результатами.

## Чтение прошивок и выбор версии

Откройте карточку устройства и Firmware Update, затем:

```python
from dji_assistant import DJIAssistant

with DJIAssistant.connect(title="DJI Assistant 2 (Enterprise Series)") as dji:
    dji.firmware.open()
    entries = dji.firmware.available()
    current = dji.firmware.current()
    target = dji.firmware.select("V17.00.0001")
    print(current, target.action)
```

- `available()` возвращает `list[FirmwareEntry]` в порядке строк UI.
- `current()` возвращает установленную `FirmwareVersion` из отдельной надписи
  Current, даже когда этой версии нет в онлайн-таблице. Это изменение раннего API:
  вместо `current.version` используйте `current`.
- `select()` принимает строку версии или `FirmwareVersion` и возвращает запись:
  **не нажимает кнопки**, не выбирает строку визуально и не запускает прошивку.
- `action` описывает подпись кнопки, а не разрешение на прошивку; доступность
  кнопки, заряд и совместимость устройства перед записью требуют отдельной проверки.
- Отсутствующие дата и метка OFFICIAL представлены `None`.
- Каждый вызов получает новое дерево через `children()`, читая каждый узел
  один раз. Глубина строки не зафиксирована; повторных обходов предков нет.
  Снимок UIA не атомарный: ошибки чтения передаются вызывающему коду.
- Неправильная страница, пустая/неоднозначная таблица, повторяющиеся версии,
  неизвестные или несколько action-кнопок, некорректные/несколько дат,
  несколько CURRENT, отсутствие CURRENT у установленной версии, присутствующей
  в таблице, и конфликт с отдельной надписью Current
  вызывают `UnexpectedAssistantState`. Отсутствующая запрошенная версия —
  `UIElementNotFound`, неправильный формат версии — `ValueError`.

На подключенном M4T чтение 10 строк заняло **0,498 с** в одном измерении;
`current()` — 0,682 с, `select()` — 0,590 с. Это измерения конкретного прогона,
не гарантированный предел времени. Подробный `firmware-probe` пока использует
старый медленный обход.

## API операций и CLI

Онлайн-операции: `dji.firmware.downgrade(target, ...)`,
`upgrade(target, ...)`, `refresh(...)`.
Обязательные параметры: `expected_device` (точное имя карточки, например
`"Matrice 4T"`) и `expected_current` (версия в формате UI, например
`"17.01.0516"`). Запись разрешается только с `confirm=True`.
Имя модели **не идентифицирует физический экземпляр**: не меняйте дрон
и не управляйте DJI Assistant вручную во время работы SDK.

```python
result = dji.firmware.downgrade(
    "17.00.0001",
    expected_device="Matrice 4T",
    expected_current="17.01.0516",
    confirm=True,
    timeout=1200,
    on_status=print,
)
```

До вызова пользователь обязан обеспечить безопасную наземную установку,
выключенные моторы, достаточный заряд, стабильное питание/USB и отсутствие сна.
SDK не измеряет заряд, не проверяет летную пригодность и не подтверждает
подлинность пакетов. По умолчанию запись запрещена.

Реализованы:

- Проверки ожидаемой модели и Current, точной строки/действия,
  видимости/доступности кнопки и направления онлайн-перехода.
- Однократные Invoke для action и Start Update, без click-fallback или ретрая.
- Стадии confirmation/downloading/transmitting/updating/complete/failed,
  версия, проценты и код ошибки через `FirmwareStatus`.
- Офлайн Transmitting может не содержать версию; она проверяется, как только
  появляется. Офлайн-диалог требует питание/USB, онлайн — также интернет.
- Завершение требует Update Complete с целевой версией и 100%, затем
  проверку standalone Current. Для Refresh неизменная Current без наблюдения
  завершения не считается доказательством успеха.
- `FirmwareOperationFailed` содержит код отказа приложения.
  Таймаут, ошибка Invoke/UIA, смена цели или неоднозначный результат после action
  дают `FirmwareOutcomeUnknown`: **не повторяйте запись автоматически**.
  Таймаут SDK не отменяет операцию устройства.
- В одном Python-процессе одновременно допускается одна операция записи.
  Межпроцессной блокировки нет; не запускайте несколько CLI/SDK одновременно.
- SDK не отменяет запись и не закрывает DJI Assistant при выходе.
  Неожиданные Confirm/Ignore не нажимаются.

CLI (флаг `--window-title` перед подкомандой):

```powershell
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" current
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" list
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" status
```

Пример записи, только после подготовки устройства:

```powershell
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" downgrade 17.00.0001 --expected-device "Matrice 4T" --expected-current 17.01.0516 --yes
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" refresh --expected-device "Matrice 4T" --expected-current 17.00.0001 --yes
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" upgrade 17.01.0516 --expected-device "Matrice 4T" --expected-current 17.00.0001 --yes
```

Без `--yes` команды записи отклоняются до подключения. Ошибки дают ненулевой
код завершения; неизвестный результат не означает, что запись не началась.

## Offline ZIP

`dji.offline.select_package(path)` выбирает пакет без запуска записи.
`selected_package()` читает выбранный путь.
`upgrade(path, target, expected_device=..., expected_current=..., confirm=True)`
проверяет ZIP, сверяет/выбирает точный путь, затем нажимает Start Upgrade.

Проверяются существование ZIP, CRC, отсутствие шифрования, дубликатов и опасных
путей, наличие одного config `.cfg.sig`. Для записи поддержан наблюдаемый формат
M4T: `wa345t_0000_v<version>_*.cfg.sig`; target сверяется с версией в имени config,
например **17.02.0501**, а не с четырехкомпонентным именем загрузки 17.02.05.01.
Это проверка структуры и имен, **не криптографической подписи DJI**.
Используйте исходный официальный ZIP. BIN не поддержан SDK.

```powershell
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" offline-select "C:\dev\fw_list\m4t\M4T_UAV_17.02.05.01_pro.zip"
dji-assistant --window-title "DJI Assistant 2 (Enterprise Series)" offline-upgrade 17.02.0501 "C:\dev\fw_list\m4t\M4T_UAV_17.02.05.01_pro.zip" --expected-device "Matrice 4T" --expected-current 17.01.0516 --yes
```

Файловый диалог определяется по цепочке владельцев окна DJI Assistant,
а не по локализованному заголовку. Ввод/Открыть используют стандартные числовые
AutomationId Windows; чужие диалоги не используются. Проверяется, что поле
не перекрыто другим окном, и что приложение отображает точный выбранный путь.
Если диалог не найден или его структура неизвестна, SDK явно останавливается
без Start Upgrade; допустим ручной выбор ZIP с последующей проверкой пути.
Автоматический выбор диалога покрыт mock-тестами, но успешный полный выбор
в текущей настольной сессии пока не подтвержден.

**Форма сохраняет выбранный путь между заходами.** `offline-select` не сбрасывает
его и ничего не прошивает, но последующий ручной клик Start Upgrade может
использовать ранее выбранный пакет. На новом M4T пользователь сообщил о таком
запуске; SDK сам запись на новом экземпляре не запускал. Наблюдался офлайн-диалог
с Start Update, требованиями питания и USB, затем Transmitting/Updating.

## Запуск и штатное закрытие приложения

`DJIAssistant.launch(executable, title=...)` запускает установленный EXE через
Windows Shell с рабочим каталогом приложения либо подключается к существующему
окну. При настольной проверке прямой subprocess-запуск launcher завершался
с кодом 0 без окна; запуск через Windows Shell открыл Enterprise Series.
`open_device("Matrice 4T")` ожидает точную, однозначную карточку и вызывает ее
один раз; при отсутствии карточки явно завершает ожидание с ошибкой.
После перезапуска в текущей сессии карточка M4T не была найдена через UIA
за 30 секунд: SDK сообщил ошибку, ни карточка, ни действие прошивки не вызывались.
Затем карточка Matrice 4T подтверждена как на скрине пользователя, так и
на независимом PrintWindow-снимке того же окна SDK. При этом свежие чтения
UIA Document по-прежнему содержали только элементы стартовой страницы,
без CONNECTED DEVICES и Matrice 4T. Это расхождение визуального состояния
и Accessibility-дерева, а не доказательство отсутствия подключения.
Автоматический обход этого расхождения пока не реализован.
Проверен запуск штатного EXE с `--force-renderer-accessibility` через
Windows Start-Process: окно открылось, но флаг отсутствовал в командных
строках DJIBrowser и renderer. Следовательно, такой запуск не подтверждает
включение полной Accessibility; добавлять этот флаг в SDK как исправление
пока нельзя. Прямой запуск DJIBrowser в обход штатного launcher не проверен.
Попытка `os.startfile` с этим флагом не создала окно за 20 секунд;
после проверки отсутствия процессов приложение восстановлено через Start-Process.
Полный startup-to-device сценарий пока не подтвержден.

Повторная read-only проверка 2026-10-04 (два прогона, без записи прошивки):

- Исходно подтверждены Matrice 4T, Current 17.02.0501 и idle; штатное
  закрытие с подтверждением Quit Now выполнено успешно.
- Прогон 1 через MCP RunCodeSnippet: `DJIAssistant.launch()` с обычным
  `os.startfile` не обнаружил окно за 30 секунд. Перед следующим запуском
  проверено отсутствие процессов launcher/DJIBrowser.
- Прогон 2 тем же SDK из терминала: новое окно запущено за 1.35 секунды,
  `open_device("Matrice 4T")` вернулся, но немедленный `current()` завершился
  ошибкой `Current label has invalid version`. Последующее отдельное чтение
  подтвердило Current 17.02.0501, idle и 10 онлайн-строк.
- На странице обнаружен FlySafe-запрос; подтверждение не выполнялось.
  Ни прошивка, ни обновление базы не запускались.

Причина различия запуска через MCP и терминал не установлена. Кроме того,
`open_device()` сейчас проверяет наличие имени модели и метки Current,
но не готовность значения версии: возврат метода не гарантирует, что
немедленный `current()` уже сможет прочитать версию. Поэтому два стабильных
успешных end-to-end прогона пока не подтверждены.

Последующая диагностика выявила причину пропуска карточки: в UIA Raw View
есть `CONNECTED DEVICES` и `Matrice 4T`, но текст модели имеет
`IsControlElement=False` и не попадает в обычный поиск descendants.
SDK теперь использует ограниченный Raw View поиск только на стартовой
странице с `CONNECTED DEVICES`. Для найденного текста без InvokePattern
выполняется один клик по его UIA-границам с проверкой принадлежности точки
окну Assistant; это не поиск по изображению и не фиксированные координаты.
После перехода SDK ожидает корректно читаемый Current.
Живой переход занял 11.36 с. Следующий новый запуск и открытие устройства
тем же SDK заняли суммарно 9.55 с, Current подтвержден как 17.02.0501.

При переходе к разрешенному Downgrade обнаружена дополнительная ошибка:
парсер считал даты `2026-04-29` и `2026-02-13` в таблице за неоднозначные
коды ошибки на экране требований. Коды теперь разбираются только в FAILED;
добавлен регрессионный тест. После read-only проверки уже открытого диалога
продолжено ожидание существующего Downgrade, без повторного нажатия строки.
Start Update запустил Downloading цели 17.00.0001. Обе операции завершены:
Downgrade 17.02.0501 -> 17.00.0001 показал COMPLETE/100% в 13:31:41,
затем SDK подтвердил Current 17.00.0001 в 13:31:45.
Метод SDK `refresh()` прошел Confirmation -> Downloading -> Transmitting ->
Updating -> COMPLETE/100% в 13:36:10; проверка Current завершена в 13:36:13.
Финальное чтение в 13:36:14: Current 17.00.0001, idle.
Refresh подтвержден экраном завершения, а не только неизменной версией.
Первый Downgrade потребовал продолжения существующего диалога после
исправления парсера; полностью непрерывный сценарий без вмешательства
этим прогоном не подтвержден. FlySafe закрыт через Ignore:
обновление базы не запускалось. После исправлений прошли 68 unit-тестов
и diff --check.

`quit_application()` закрывает приложение только при распознанной idle-странице
прошивки, подтверждает единственную кнопку Yes внутри диалога `Quit Now?`
один раз и проверяет исчезновение окна. Принудительное завершение не используется.
Это отдельно от `close()` и выхода из `with`, которые только освобождают
соединение SDK. Штатное подтверждение уже открытого Quit Now проверено на
Enterprise Series: приложение закрылось без запуска прошивки.

Дополнительные read-only проверки 2026-10-04:

- Два последовательных штатных перезапуска с открытием карточки и чтением
  Current 17.00.0001 прошли за 7.74 и 7.82 с. FlySafe обнаружен и закрыт
  через Ignore, без обновления базы.
- Приложение может открыть страницу Offline Upgrade при входе в устройство.
  `open_device()` теперь один раз переходит на Firmware Update и ожидает Current.
- Native file picker оказался вложенным UIA Window основного окна Assistant,
  а не отдельным результатом Desktop.windows. Поиск расширен на оба источника,
  с дедупликацией handle и обязательной проверкой цепочки владельца.
  На реальном открытом диалоге подтверждены ComboBox 1148 и Button 1;
  SDK выбрал официальный ZIP и прочитал полный путь обратно из формы.
  Start Upgrade не нажимался. Полный вызов select_package с открытием нового
  диалога после этого исправления еще требует live-проверки.
- Следующий запуск показал `Waiting for Backend to boot up ...` и
  DJI Assistant Terms of Use с кнопкой Agree. Причина повторного появления
  условий не установлена. SDK не принимает условия автоматически:
  open_device сообщает отдельную ошибку; ожидание backend имеет отдельную
  причину таймаута. Наличие окна после launch не означает готовность backend.
  По сообщению пользователя, startup-последовательность потребовала трех
  Agree и затем Consider Later; SDK эти кнопки не нажимал. После действий
  пользователя формы исчезли, но отдельное ожидание 45 с по-прежнему
  завершилось backend timeout. DJIService, DJIServiceCore и DJIBrowser
  присутствуют; наличие процессов не доказывает готовность backend.
  Причина зависшего состояния пока не установлена; дальнейшая live-проверка
  полного offline-select остановлена, новых записей прошивки не было.
  Текущий набор после этих изменений: 73 теста, compileall и diff --check прошли.

Offline live-прогон 2026-10-04: SDK автоматически выбрал официальный ZIP,
подтвердил требования и прошел Transmitting -> Updating -> COMPLETE/100%
для 17.02.0501 в 13:57:44. Первый результат метода был FirmwareOutcomeUnknown:
после Back метка Current уже появилась, а версия еще не отрисовалась.
Независимое read-only чтение подтвердило Current 17.02.0501, idle, без
повторной записи. Проверка результата теперь ожидает читаемый Current
в пределах исходного timeout; при истечении срока сохраняет причину ошибки.
Валидная версия, отличная от цели, по-прежнему немедленно отклоняется.
Исправление покрыто тестом; новый повторный live-write не выполнялся.
