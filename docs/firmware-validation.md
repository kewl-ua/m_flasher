# Прошивка M4T: журнал живых проверок

[Главная и карта документации](../README.md)

Исторические снимки и отдельно разрешенные операции через штатный UI. Успех скрипта или ручного действия не означает end-to-end проверку соответствующего метода SDK.

Материалы ниже сохраняют ход исследования. Последующие записи могут уточнять ранние гипотезы; ограничения приведены рядом с результатами.

## Результаты проверки на Matrice 4T — 2026-10-04

Проверка выполнена на подключенном к компьютеру M4T в
DJI Assistant 2 (Enterprise Series). Текущая прошивка: **V17.01.0516**.
Команда `firmware-probe` завершилась с кодом 0.
Операции Refresh, Downgrade, Upgrade и Update не выполнялись.

Подтверждено на этом устройстве и экране:

- До открытия карточки M4T UIA видело только оболочку окна. После открытия
  карточки стали доступны Firmware Update, название Matrice 4T и таблица.
- Найдено 11 упоминаний версий: 10 строк таблицы и отдельная надпись
  текущей версии. Надпись текущей версии не выделена как строка таблицы.
- Для всех 10 строк минимальный родитель с одной уникальной версией
  и action-кнопкой найден на два уровня выше текста версии.
- Префикс `V` в строках таблицы представлен отдельным текстовым элементом;
  сам номер версии читается без него.

| Версия | Дата в UI | Кнопка в UI |
|---|---|---|
| 17.01.0516 | 2026-04-29 | Refresh |
| 17.00.0001 | 2026-02-13 | Downgrade |
| 16.01.0006 | 2025-12-22 | Downgrade |
| 14.03.0012 | 2025-10-10 | Downgrade |
| 14.03.0009 | 2025-08-25 | Downgrade |
| 14.01.0012 | 2025-06-14 | Downgrade |
| 13.01.0010 | 2025-04-11 | Downgrade |
| 12.01.0607 | 2025-03-10 | Downgrade |
| 12.01.0606 | 2025-02-21 | Downgrade |
| 12.00.0107 | 2024-12-28 | Downgrade |

Это снимок списка, показанного приложением, а не гарантия доступности
прошивок или возможности отката. У версии 14.03.0012 не наблюдалась метка
OFFICIAL; причина отсутствия метки не установлена.

Исправлена ошибка разделения объектов pywinauto: сессия хранит
`WindowSpecification` для поиска через `child_window()` и ожиданий,
а `UIAWrapper` — для обхода дерева. При закрытии сессии освобождаются обе
ссылки, само приложение DJI Assistant не закрывается.
Три регрессионных теста проверяют это разделение, состояние без подключения
и передачу явного заголовка окна:

```powershell
python -m unittest discover -s tests -v
```

## Выводы для следующего этапа

- Структура использована для реализации `available()` и `current()`;
  результаты их проверки приведены в [Windows SDK](./windows-sdk.md).
- Глубина 2 подтверждена только для этой проверки; нельзя фиксировать ее
  как универсальное правило для других устройств и версий приложения.
- Проба выполняет повторные обходы UIA и работает медленно. Следующий этап —
  сократить эти обходы и измерить время выполнения.
- Успешное чтение UI не проверяет операции прошивки. Consumer Series после
  исправления на реальном устройстве повторно не проверялась.

## Экспериментальные операции на M4T — 2026-10-04

После read-only пробы с отдельным подтверждением пользователя выполнены
операции через штатный UI DJI Assistant, не через готовые методы SDK:

| Операция | Переход | Проверенный результат |
|---|---|---|
| Downgrade | 17.01.0516 → 17.00.0001 | Update Complete!, 100%; Current 17.00.0001 |
| Refresh | 17.00.0001 → 17.00.0001 | Update Complete!, 100%; Current 17.00.0001 |
| Upgrade | 17.00.0001 → 17.01.0516 | Update Complete!, 100%; Current 17.01.0516 |

Наблюдались стадии Downloading, Transmitting и Updating; проценты относятся
к каждой стадии отдельно. После успешного завершения интерфейс меняет
CURRENT и кнопки Refresh/Upgrade/Downgrade согласно установленной версии.
У Downgrade и Refresh/Upgrade наблюдался диалог с кнопкой Start Update
и требованиями интернета, питания устройства и USB.

В прогоне Downgrade переход к Downloading произошел до нажатия Start Update
скриптом: проверка состояния остановила скрипт. Источник запуска не установлен.
В прогонах Refresh и Upgrade скрипт явно нажал Start Update по одному разу.
Это различие необходимо учитывать при проектировании автомата состояний:
нельзя повторять нажатие после таймаута без повторного чтения текущей стадии.

После операций пользователь сообщил об успешной летной проверке.
SDK сам не проверял летную пригодность, совместимость пульта или Pilot 2.
Результаты относятся к конкретному M4T и этим версиям, не ко всем переходам.

## Offline Upgrade — начальное исследование

На реальном экране UIA обнаружены:

- надпись Local version и значение `00.00.0000` без выбранного пакета;
- поле Edit: `Click here to select firmware zip package...`;
- кнопка Start Upgrade, активная даже без выбранного пакета.

Следовательно, активность кнопки не подтверждает валидность пакета.
Проверки содержимого пакета и подписи/модели приложением не установлены.
Для следующего шага нужен предназначенный для M4T пакет из доверенного источника.
Поддержка Offline Upgrade в SDK описана в [Windows SDK](./windows-sdk.md#offline-zip).

Предоставленный для исследования файл имеет имя
`V17.00.0001_wa345t_dji_system.bin`, размер 665835520 байт и начинается
с `wa345t.cfg.sig`, а не с заголовка ZIP. На скрине пользователя подтвержден
стандартный диалог Windows с фильтром `All Files (*.*)`. После выбора BIN
пользователем полный путь отображается в Edit, что также проверено через UIA.
Файл не переименовывался; подпись поля про ZIP не ограничивает выбор BIN.
Однако принятие пути не подтверждает совместимость или валидность контейнера:
Local version после выбора остается `00.00.0000`, причина не установлена.
Первоначальная попытка найти диалог через UIA не дала результата; это не
доказательство отсутствия диалога. Автоматизация выбора файла требует
отдельной проверки обнаружения и принадлежности диалога приложению.

## Проба запуска выбранного BIN — 2026-10-04

По отдельному подтверждению пользователя Start Upgrade нажата через UIA
один раз для указанного файла. Пользователь сообщил, что пакет получен
из официальной загрузки/кеша DJI Assistant для этого M4T; SDK не проверял
его подпись или соответствие формату Offline Upgrade.

Приложение показало `Update failed.`, код `2-251-1`, прогресс `0%`.
Отдельного диалога подтверждения в этом прогоне не наблюдалось.
После Back и открытия Firmware Update метод `current()` прочитал
`17.01.0516`, action — Refresh. Повторный запуск не выполнялся.

Причина ошибки не установлена: нельзя считать этот код доказательством
неподдерживаемого расширения, повреждения пакета или запрета отката.
Также прогресс 0% сам по себе не доказывает отсутствие обращений к устройству.
Для дальнейшего исследования нужны журналы DJI Assistant и проверка требований
к офлайн-пакету; менять контейнер или повторять запись наугад не следует.

## Официальный ZIP M4T 17.02.05.01 — 2026-10-04

Пользователь предоставил `M4T_UAV_17.02.05.01_pro.zip` со страницы загрузок DJI.
Размер — 665800202 байта; внутри 23 записи, включая подписанные компоненты
и `wa345t_0000_v17.02.0501_20260529.pro.cfg.sig`. Проверка CRC ZIP прошла
без распаковки. CRC не проверяет подпись DJI или совместимость с устройством.

Пользователь запустил процесс и сообщил об успешном завершении.
Через UIA наблюдались Transmitting до 100% и Updating с версией
`V17.02.0501`. После завершения на странице Matrice 4T через UIA прочитана
отдельная надпись `Current: V17.02.0501`. Итоговый экран Update Complete
для этого прогона скрипт не зафиксировал.

Обнаружен новый корнер-кейс: установленной офлайн-версии нет в онлайн-таблице,
которая содержит 10 предыдущих версий с кнопками Downgrade и ни одной метки
CURRENT. Ранняя версия парсера отклоняла это состояние с `UnexpectedAssistantState`
(`Expected one CURRENT firmware row, found 0.`). Это ограничение SDK,
а не сообщение об ошибке прошивки. Теперь чтение установленной версии отделено
от доступных строк таблицы, без выдуманных action или даты для офлайн-версии.

Также приложение показало `Updating No-fly Zone Database is required. Update now?`
с кнопками Confirm и Ignore. Скрипт их не нажимал: обновление базы зон —
отдельная операция, не часть подтверждения успешной установки прошивки.
