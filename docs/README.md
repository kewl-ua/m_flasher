# Карта документации

[Главная проекта](../README.md)

Документация разделена по назначению: инструкции по существующему SDK,
свидетельства проверок и исследовательские записи. Каталог исследования
не означает, что описанный подход уже доступен в SDK.

## 1. Руководства: как пользоваться SDK

| Документ | Назначение | Статус |
|---|---|---|
| [Windows SDK и CLI](./guides/windows-sdk.md) | Чтение, онлайн/офлайн-операции, запуск и закрытие | Реализовано; live-покрытие методов различается |
| [IsolatedAssistant и CLI](./guides/isolated-assistant.md) | Отдельный desktop, attach, выбор ZIP | Экспериментально; запись прошивки запрещена |

Начинайте с руководства обычного SDK. Для скрытого режима сначала прочитайте
его ограничения; не переносите команды записи обычного режима в isolated.

### Маршрут к Linux updater

[Справочник адресов DUML](./research/transport/usb-duml.md#справочник-адресов-duml)
сводит type/index, публичные имена, наблюдаемые роли на M4T и связь с
manifest/status prefixes. Header-адреса и payload prefixes разделены
по уровню подтверждения; USB addresses описаны отдельно.

Новое live-свидетельство, проверенное offline:
[USB передача 23 файлов release 17.01.0516](./research/firmware/capture-transfer.md).
Подтверждены file bytes/MD5 и направление команд; полный session/apply
workflow и Linux implementation пока не подтверждены.

[Сравнение с Offline Upgrade 17.02.0501](./research/firmware/capture-offline-upgrade.md):
config совпал с нашим ZIP побайтно, 22 firmware — по SHA256.
Добавлены управляющая последовательность двух прогонов, ACK timing,
расширенные `42`, terminal и post-reconnect `4F`; границы схемы и recovery
остаются открытыми.

[Первый самостоятельный Windows Refresh: проверка журнала](./research/firmware/direct-refresh-journal.md).
2444 сохраненных кадра проверены по CRC; terminal и ответы версии
подтверждают описанный результат 17.02.0501 -> 17.02.0501.
Отчеты о файлах отделены от отсутствующих в JSONL data chunks.
Внешняя реализация не интегрирована; Linux и смена версии не проверены.

Подробный [каталог XML manifest и ZIP entries](./research/firmware/package-manifest.md)
фиксирует все 22 компонента, config bounds, metadata и значения атрибутов,
отдельно от неподтвержденной семантики native updater.

1. [Пакет и manifest](./research/firmware/linux-updater.md): состав, варианты
   аппаратуры и upgrade center; MD5 не заменяет проверку подписи.
2. [Native consumer и dispatch](./research/native/analysis.md): установленные
   связи и оставшиеся границы статической трассировки.
3. [USB transport](./research/transport/usb-duml.md): проверенные framing,
   адреса и ограничения конкретного Windows-драйвера.
4. Следующая исследовательская граница: raw capture внешнего writer,
   проверка его реализации, выбор компонентов, полный firmware-session
   contract и recovery. Linux transport и интеграция writer не проверены.

### Как читать степень подтверждения

- **Unit**: проверка кода без устройства, не доказательство wire-совместимости.
- **Offline/static**: файл, parser, metadata или disassembly; не доказательство
  выполнения найденной ветки подключенным устройством.
- **Live**: конкретный эксперимент на M4T; не универсальность для других
  устройств, драйверов или версий.
- **Кандидат/гипотеза**: требует следующей независимой проверки.

Исследовательские документы сохраняют хронологию: поздние записи могут
уточнять ранние гипотезы. Ограничения относятся к конкретному результату.
Прошлые разрешения на однократные запросы исчерпаны; новые live-запросы,
захваты и firmware writes требуют отдельного согласования.

## Правило размещения новых материалов

- `guides/`: пользовательские сценарии и контракты существующего API/CLI.
- `validation/`: тестовое покрытие и журнал проверенных результатов.
- `research/transport/`: USB, ABI, endpoints, DUML framing и correlation.
- `research/telemetry/`: интерпретация показаний и независимые сверки.
- `research/native/`: статические адреса, ownership, parser/dispatch и Qt/Go.
- `research/firmware/`: пакет, применимость, протокол и recovery updater.
- `research/windows/`: экспериментальные способы автоматизации Assistant.

Общие факты храните в профильном документе, а в остальных давайте ссылку.
Всегда отделяйте наблюдение от гипотезы и исторический результат от
текущего состояния устройства.
